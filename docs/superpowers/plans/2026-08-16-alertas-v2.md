# Entrega de alertas v2 — plano de implementação

> **Para trabalhadores agênticos:** SUB-SKILL OBRIGATÓRIA: use `superpowers:subagent-driven-development` (recomendado) ou `superpowers:executing-plans` para implementar tarefa a tarefa. Os passos usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** entregar no canal privado `#github-alerts` exatamente o que o app oficial "GitHub for Slack" não sabe entregar — alerta de segurança e execução de workflow que falhou — sem nunca perder um alerta, aceitando duplicata.

**Arquitetura:** o ingress que já roda no `main` é mantido (HMAC antes de parsear, allowlist, normalização, linha durável com o GUID como chave, publicação na fila). Tudo depois dele é novo e pequeno: três estados (`pending` → `sent` | `failed`), um consumidor que posta e grava o desfecho, um cron que reenfileira por idade, um endpoint de status protegido, e um vigia no GitHub Actions. Não há resolver, varredura de histórico, reparo de duplicata, menu de operador, lease nem CAS de estado.

**Tecnologias:** Cloudflare Workers, D1 (SQLite), Cloudflare Queues, Vitest, TypeScript.

**Spec:** `docs/adr/ADR-002-alertas-v2.md` — o plano argumenta a partir dela; leia as duas.

### Tarefa 1: fixar os três números, com a fonte de cada um

A versão anterior desta tarefa mandava medir o recuo entre tentativas da fila com uma sonda descartável. Ela **caiu**: o recuo está documentado, a plataforma não impõe nenhum por conta própria, e a sonda exigiria implantar um Worker — o que a regra de deploy só por GHA proíbe. Um bloqueio que virou fato citado.

**Arquivos:**
- Criar: `docs/superpowers/plans/2026-08-16-alertas-v2-numeros.md`

**Produz:** `CRON_STALE_AFTER_MS`, `MAX_SEND_ATTEMPTS`, `RETRY_BASE_DELAY_SECONDS` e `ROW_RETENTION_MS`, cada um com a justificativa escrita ao lado. Nenhuma tarefa posterior inventa valor.

- [ ] **Passo 1: registrar os fatos de plataforma, citados**

Da [documentação de batching, retries e delays](https://developers.cloudflare.com/queues/configuration/batching-retries/), verbatim: *"Messages can be delayed by up to 24 hours"*; *"Each message delivered to a consumer includes an `attempts` property that tracks the number of delivery attempts made"*; e *"Messages that reach the configured maximum retries will be deleted from the queue, or if a dead-letter queue (DLQ) is configured, written to the DLQ instead."*

A plataforma não aplica recuo implícito: quem escolhe é o consumidor, via `delaySeconds`. A própria documentação dá o helper:

```js
function calculateExponentialBackoff(attempts, baseDelaySeconds) {
	return baseDelaySeconds ** attempts;
}
```

- [ ] **Passo 2: escolher `RETRY_BASE_DELAY_SECONDS` e `MAX_SEND_ATTEMPTS` juntos**

Os dois são um par: base e expoente definem quanto tempo o sistema insiste antes de desistir, e o teto é **o limite da amplificação de duplicatas** — um envio que deu certo com resposta perdida gera uma cópia por tentativa. Escrever, ao lado dos valores, a soma da série em minutos, que é a janela real de insistência, e conferi-la contra o teto da fila (`max_retries: 5`, `wrangler.jsonc:81`) de modo que o teto da aplicação dispare primeiro.

- [ ] **Passo 3: escolher `CRON_STALE_AFTER_MS`**

É o tempo máximo que um alerta pode ficar invisível antes de o cron o recuperar. Precisa ser maior que a janela de insistência do passo 2 — senão o cron republica uma linha que a fila ainda está tentando — e menor que qualquer limiar de alarme do vigia.

- [ ] **Passo 4: escolher `ROW_RETENTION_MS` com a consequência ao lado**

A linha guardada é a trava de deduplicação: o prazo define também a janela em que um reenvio do GitHub não vira segunda mensagem, e a janela em que "o que aconteceu com aquele alerta?" tem resposta. Escrever essa frase junto ao número, não em outra seção.

-- O GUID da entrega do GitHub é a chave: é ele que faz a redelivery do
-- GitHub não virar segunda mensagem (ADR-002 §5, decisão 10).
CREATE TABLE alert_delivery (
  delivery_id TEXT PRIMARY KEY NOT NULL CHECK (
    length(delivery_id) BETWEEN 1 AND 128
    AND delivery_id NOT GLOB '*[^A-Za-z0-9-]*'
  ),
  payload_json TEXT NOT NULL CHECK (json_valid(payload_json)),
  state TEXT NOT NULL CHECK (state IN ('pending', 'sent', 'failed')),
  -- Monotônico: o cron NUNCA o reinicia (ADR-002 §6, instância B).
  attempts INTEGER NOT NULL DEFAULT 0 CHECK (attempts >= 0),
  -- Estacionada: falha intrínseca à linha. É CONTAGEM, não condição de
  -- alarme (ADR-002 §6, instância C′).
  parked INTEGER NOT NULL DEFAULT 0 CHECK (parked IN (0, 1)),
  slack_message_ts TEXT,
  last_error TEXT,
  -- Âncora da idade que o vigia lê. NENHUM caminho de recuperação escreve
  -- esta coluna (ADR-002 §6, instância B).
  created_ms INTEGER NOT NULL,
  updated_ms INTEGER NOT NULL
);

-- O cron seleciona por estado e idade de ingresso.
CREATE INDEX idx_alert_delivery_pending ON alert_delivery (state, created_ms);

```ts
import {
  PERMANENT_SEND_ERRORS,
  SLACK_TS_PATTERN,
  type SendOutcome,
} from "./contract";

function parseJsonObject(bodyText: string): Record<string, unknown> | null {
  try {
    const parsed: unknown = JSON.parse(bodyText);
    if (typeof parsed === "object" && parsed !== null && !Array.isArray(parsed)) {
      return parsed as Record<string, unknown>;
    }
  } catch {
    // Corpo ilegível é incerteza, e incerteza tenta de novo.
  }
  return null;
}

// Total por construção: todo caminho retorna um SendOutcome, e o ramo
// final é `retry`. ADR-002 §8: a dúvida SEMPRE resolve para tentar de
// novo, porque duplicata é aceitável e perda não é.
export function classifySendOutcome(input: {
  httpStatus: number;
  bodyText: string;
}): SendOutcome {
  if (input.httpStatus !== 200) {
    return { kind: "retry", reason: `http_${input.httpStatus}` };
  }
  const body = parseJsonObject(input.bodyText);
  if (body === null) return { kind: "retry", reason: "corpo_ilegivel" };

  if (body["ok"] === true) {
    const ts = body["ts"];
    if (typeof ts === "string" && SLACK_TS_PATTERN.test(ts)) {
      return { kind: "sent", ts };
    }
    return { kind: "retry", reason: "ok_sem_ts_utilizavel" };
  }

  if (body["ok"] === false) {
    const code = body["error"];
    if (typeof code === "string" && PERMANENT_SEND_ERRORS.has(code)) {
      return { kind: "failed", code };
    }
    return {
      kind: "retry",
      reason: typeof code === "string" ? `desconhecido_${code}` : "sem_codigo",
    };
  }

  return { kind: "retry", reason: "forma_irreconhecivel" };
}
```

```ts
import type { AlertRow } from "./contract";

export class AlertStore {
  readonly #db: D1Database;
  constructor(db: D1Database) {
    this.#db = db;
  }

  async insert(deliveryId: string, payloadJson: string, now: number): Promise<boolean> {
    const result = await this.#db
      .prepare(
        `INSERT INTO alert_delivery
           (delivery_id, payload_json, state, created_ms, updated_ms)
         VALUES (?, ?, 'pending', ?, ?)
         ON CONFLICT(delivery_id) DO NOTHING`,
      )
      .bind(deliveryId, payloadJson, now, now)
      .run();
    return (result.meta.changes ?? 0) > 0;
  }

  // created_ms NUNCA aparece num SET. Ver o teste do invariante.
  async markSent(deliveryId: string, ts: string, now: number): Promise<void> {
    await this.#db
      .prepare(
        `UPDATE alert_delivery
            SET state = 'sent', slack_message_ts = ?, last_error = NULL,
                updated_ms = ?
          WHERE delivery_id = ?`,
      )
      .bind(ts, now, deliveryId)
      .run();
  }

  async markFailed(
    deliveryId: string,
    code: string,
    parked: boolean,
    now: number,
  ): Promise<void> {
    await this.#db
      .prepare(
        `UPDATE alert_delivery
            SET state = 'failed', last_error = ?, parked = ?, updated_ms = ?
          WHERE delivery_id = ?`,
      )
      .bind(code, parked ? 1 : 0, now, deliveryId)
      .run();
  }

  async bumpAttempt(deliveryId: string, now: number): Promise<void> {
    await this.#db
      .prepare(
        `UPDATE alert_delivery
            SET attempts = attempts + 1, updated_ms = ?
          WHERE delivery_id = ?`,
      )
      .bind(now, deliveryId)
      .run();
  }

  // ADR-002 §4: por IDADE, incondicional, sem conhecer o estado da fila.
  async staleRows(now: number, olderThanMs: number, limit: number): Promise<AlertRow[]> {
    const result = await this.#db
      .prepare(
        `SELECT * FROM alert_delivery
          WHERE state = 'pending' AND created_ms <= ?
          ORDER BY created_ms ASC
          LIMIT ?`,
      )
      .bind(now - olderThanMs, limit)
      .all();
    return result.results.map(toAlertRow);
  }
}
```
